## 共通协议和组件

服务端默认时间：intro 15s → card 6s → countdown 3s → playing（一般上限 60s；灯市按题计时）→ result 5s → transition（普通 2s；七宝市后 wind 8s；市散后 rebirth 6s）→ 下一关；可提前结束或主持跳过。结束 ending 50s → finished。配置可覆盖默认值，一律用服务端截止时间计算，不把时间写死在素材里。每局仅一个 intro；“4个开场”是四镜头还是四片段待用户确认，未新增节点。入场最多 32 个等待席，2 人起可由主持开始；开局后加入及满席者观战。主持跳过/直接结局会改变正常流程，结果必须读 result 和 championId，不根据视觉推断。

手机基准横屏 844×390 CSS px；safe rectangle 为视口减去 env(safe-area-inset-*) 后，再内缩 12px。尺寸为设计目标而非当前 CSS 实装：左上状态 250×36；左上方向图 88×88，距安全区左 18、上 48；右上信息最多 360×76，右侧 64px 全屏按钮；左下摇杆 100×100、右下跳 100×100，距安全区左右 25、底 22。小于 320px 高时摇杆与按钮 80×80、方向图 68×68。触区至少 44×44，标题与题面换行，不可覆盖操控区；长题最多两行并随空间缩字到 16px，下限不达时应提供可滚动的题面区而不是遮挡按钮。屏幕中心供世界目标与人物；各层遵循：视频/状态消息覆盖场景，安全提示在其上，主持控件不可出现在手机。接入时应处理实际刘海、动态视口、输入键盘、竖屏引导。手机跟随活动角色，镜头约角色后方 (0,+3.4,+4.6)，看向 (0,0,-1.2)；非活动/观战回到大屏式全场，不承诺自由切换。

大屏基准 1920×1080，安全区各边 5%（96×54）。画面主体在左侧约 75%，右侧 240 CSS px 面板为现有桌面基准，生产版可按 1920 设计为 300×780（右距安全边 0，顶距安全边 0）；上方关名/计时位于安全区内，底部主持栏可收纳但不得隐藏权限或误触。UI 尺寸按目标投影实际视距验证，长名单滚动/分页，不把人数画进底图。场景镜头目前 (0,26,25)，看向普通场 (0,0,0)、桂市 (0,0,-2)，大屏固定俯瞰；所有建议摆件需从两种机位试遮挡。画布截图中的示意网格及字段是标注，最终美术需重建可拆分组件。

统一动态来源：`room.players` 的 name/connected/status；`match.phase/phaseEndsAt/phaseId`；`level.id/data`；`world.players[id].avatar`；`match.activeIds/results/championId`；`media.{id,endsAt,displayUrl,phoneUrl}`。时间由 `serverTime` 与本机偏移估算；重连与媒体失败使用“连接中断，正在重连”及“过场进行中”。资格结果以 `results` 中名单为准。当前手机 result 对非 eliminated 的 spectating 也会显示“本关晋级”，设计应按名单区分观战，需开发修正后验收。显示队伍、榜单、题目答案等扩展排版中，若现有客户端没有该面板，属于接入需求，不冒充现有功能。无 podium、额外玩家开始或再来一局按钮。

当前 `/admin/bootstrap` GET 返回 host token，大屏 attach 后可调用 `host:start/skip/finish/reset` 与 `host:bots:add/clear`；令牌并非用户身份认证，服务端在当前实现对 bootstrap 未鉴权。仅供可信现场网络，生产部署权限隔离需要开发处理，视觉上不能替代服务端鉴权。移动端玩家操作仅已连接、playing 状态、countdown 或 playing；countdown 可移动和跳但不结算玩法；观战/淘汰不可操作。客户端目前 result 的文案缺陷不应被设计固化。

原点和坐标均为游戏单位，非已实现物理米制。普通场地 20×20：x,z 在 [-10,10)，tile 列 floor(x+10)、行 floor(z+10)，索引 row×20+col。出生按 i：x=(i%8)-3.5，z=floor(i/8)，最多 32 人。锦、灯、七宝、酒有边界 x/z ±9.6，市散无此围栏。外围摆件全部以锚点为中心，足迹原则上在 |x|≥10.5 或 |z|≥10.5；不得加入不可见碰撞或干扰服务器判定。推荐位置是设计锚点，尺寸和遮挡须在目标设备调校，不是服务端生成对象。共享模块 MOD-COM-001~006，玩家 CHR-COM-001~004，界面 UI-COM-001~015。灯牌、酒坛与终点标记的字、数字、判定由程序绘制。

手机在角色活动时跟随且视野贴近地面，大屏固定高位俯瞰，天空可能在某些机位仅露少量或不可见；制作前先按实际机位确认可见范围，不能靠天空盒承担题面、目标或关键地标。视频阶段由全屏影片覆盖场景，天空与远景只用于非媒体场景；切关和断线恢复应避免错误关卡背景闪现。验收在实际手机横屏和目标大屏分别截取大厅及六关的 card、countdown、playing、result：检查图像接缝、色调与场景衔接、地平线、边缘裁切、角色／答案／地格对比度、加载失败纯色回退、切关错图、低端设备内存和帧率。视频播放与声轨仍按媒体规范单独验收。

## 大厅 00

开场为扫码/入场，手机“你的名字”“角色颜色”“进入游戏”；微信环境先显示浏览器打开引导。入场后“等待开局”，无大厅 avatar 与摇杆；大屏显示真实二维码、链接、连接人数和玩家状态。主持可添加/移除机器人并开始，≥2 个已连接等待玩家才允许开局。大厅结束由 host 开始进入 intro；视频结束自动进入锦市卡片。背景复用锦市，仅作静态氛围：市门 (0,-12)、织机 (-6,-12)、锦架 (6,-12)，无需阻挡白模。ID：DES-LOB-001、ENV-COM-001、UI-COM-001/002/003/013/014、VID-INT-001/002。验收：真实二维码扫码和浏览器引导；无假二维码、玩家开始或摇杆；满席和中途入场按观战显示；双端切到同一 intro。

## 锦市 01

汉代织锦交易，织机 (-6,-12)、市门 (0,-12)、晾架 (6,-12)、左右摊 (±12,±5)；模型足迹在边界外。400 格独立染色，数据 `owners[index]`；队伍 `teams` 和 tileCount，人数≥8 分4队、≥4分2队、更少按人数分队；轮流分配。60s 到期淘汰面积最小队；同分依据 reachedAt 和队伍顺序，勿在图上预设结果。开场卡显示实际规则，游玩手机展示本人队伍、面积及方向图；大屏展示队伍色/面积为设计扩展（现有大屏没有队伍面积面板），结束手机按名单展示晋级/淘汰/观战，大屏显示晋级数。ID：ENV-JIN-001、BG-JIN-001、DES-JIN-001、PRP-JIN-001~006、FX-COM-001、UI-COM-005/006/009/015。验收：400 格与 owners 一致；多队颜色同时可辨，手机自身位置可见；按真实结算显示且无预设获胜队。

## 灯市 02

灯树 (0,-12)、灯摊 (±12,-5)、题灯 (-6,-12)、答案灯可对应 x=-7/0/7。三答案区真实判定 A: x<-4，B: -4≤x<4，C: x≥4；颜色块与 A/B/C 标识不能掩盖边界。最多5道，从当前五道占位题随机排序；每题作答10s、揭晓2s、非末题恢复2s，答错即淘汰；剩余≤1或第五题揭晓后结算，全员答错可无人晋级。答案揭晓前 `answer=null`；恢复阶段当前 UI 也显示“揭晓”，设计可明确“准备下一题”，需开发修改。手机按移动位置答题，没有点击选项按钮；大屏显示题干、三选项、题号与动态时间。现有代码不使错误区域塌落。ID：ENV-DEN-001、BG-DEN-001、DES-DEN-001、PRP-DEN-001~004、UI-COM-007/015、CNT-DEN-001。验收：边界 -4、4 分区正确；不泄露答案；2 秒揭晓/恢复及零存活、提前结束可显示，无 16 秒假倒计时。

## 七宝市 03

寺门 (0,-12)、交子铺 (-7,-12)、珠宝摊 (7,-12)、其他摊 (±12,±5)；动态交子通过 `items` 单独放置，出生坐标 x/z 在 [-9,9]，2s 后落地、再保留8s，距玩家≤0.8自动拾取。出生速率随存活人数变化。60s 结束，按数量降序、达到该数量的时间及入场顺序排序，晋级目标为 rank(n,0.65)：n=2 时1，否则 min(n-1,max(2,round(n×0.65)))。手机展示本人数量/方向图；大屏排名面板是提案，须开发绑定 `scores` 和排序逻辑。结束用真实晋级名单；随后 wind 8s（仅仍有多人且继续时）。ID：ENV-QIB-001、BG-QIB-001、DES-QIB-001、PRP-QIB-001~005、FX-COM-003、UI-COM-008/015、VID-WND-001/002。验收：落地前不能拾取、过期消失，数量和并列顺序与服务端一致。

## 市散 04

沿用七宝市空间，收摊铺面 (±12,-5)、倒幡 (±12,5)、散货筐 (±7,-12)，落纸不遮危险格。普通 400 格，开局 1s 保护；其后踩上未触发格，600ms 后消失，y<-5 淘汰。存活人数≤目标后等待200ms结算；目标 rank(n,0.6)，同时落下有服务器回溯处理；60s 超时取存活者。手机危险格方向图、存活状态；大屏存活数可由状态计算（需接入）。结果以服务器名单为准，进入下一关时 rebirth 6s。ID：ENV-SAN-001、BG-SAN-001、DES-SAN-001、PRP-SAN-001~003、FX-COM-002/005、UI-COM-009/015、VID-REB-001/002。验收：保护与预警可区分，格子消失由 disappearsAt 驱动，晚落和同时落的结果不由动画自行判定。

## 酒市 05

酒坊 (0,-12)、甑灶 (-6,-12)、粮仓 (6,-12)，四角交付中心 (-8,-8)、(-8,8)、(8,-8)、(8,8)，判定半径1.5；坛模型不挡玩家或交付圈。初始粮袋 max(6,活跃人数×2)，位置随机 x/z [-6.5,6.5]；距0.8自动拾起，一人最多携一袋，拾起后约1s再生；进交付圈自动交付、得1分，3袋立即晋级。目标 rank(n,0.6)；满额提前结束，60s 不足按已晋级及计分排序补足。手机“运粮 {count}/3”和四点方向图；大屏已晋级/目标为提案，需绑定 qualifiedIds/targetCount。没有拾取或交付按钮。ID：ENV-JIU-001、BG-JIU-001、DES-JIU-001、PRP-JIU-001~005、FX-COM-006/007、UI-COM-008/015。验收：携带与四个交付圈位置一致；数量、提前晋级、超时补足与服务器一致。

## 桂市 06

10列×20行，列中心 x=-4.5..4.5，行中心 z=9.4-1.2×row，地面高度 0.35×row；出生 z=9。行5/10/15 各有随机连续3或4格缺口；服务端顶台 row20–23、y=7（当前白模未单独绘制顶台，生产美术及接入需补齐）；目标中心 (0,-15)，平面距离≤1 且角色 y≥7 获胜。踩中格 800ms 后消失；从开局第3秒起按行向上消失，间隔从1500ms递减到600ms。60s 超时取存活者最靠前者，生存结算也有回退；单人可提前获胜。桂枝仅标记终点，当前没有点击/采摘动作；灯楼 (0,-16.5) 和桂摊/码头 (±7,-8、±7,6) 不占赛道。手机方向图有终点；大屏全赛道需保持可辨，实际镜头遮挡须验证。结束以 championId 展示冠军或无人夺冠；ending 50s 仅大屏覆盖动态冠军文字，手机现有视频没有冠军叠字，finished 双端显示结果。ID：ENV-GUI-001、BG-GUI-001、DES-GUI-001、PRP-GUI-001~005、UI-COM-009/010/015、VID-END-001/002。验收：200格、缺口、顶台和终点匹配状态；无需按钮；无虚构领奖台或固定名字。

## 媒体与生产交接

现存 8 个 MP4 均为 960×540、15fps、无音轨测试卡，手机版本为副本（见 `production/media/placeholder/README.md`），不是成片。推荐交 1920×1080 H.264/AAC 横屏双端版本与源工程，素材安全区和内容依目标屏实际验证；同步 `intro/wind/rebirth/ending` 15/8/6/50s，不一致需先改服务器配置并回归。手机静音自动播放，大屏尝试有声，失败会静音重试；失败显示“过场进行中”，进度不等待播放。当前中途重连是否精确追帧需要实际验证，不能假定媒体自动 seek。各项负责人待认领，内容来源、版权、历史审校和真实终端验收待完成。
