## 1. 概述

| 项 | 内容 |
|---|---|
| 名称（暂定） | 锦江十二月市 · 千年赶集 |
| 类型 | 多人派对淘汰赛（类蛋仔派对），穿插历史 |
| 平台 | **手机端优先**：手机浏览器（H5 + WebGL），横屏，扫码即玩；大屏固定俯视全场并播放结局 |
| 单局 | 最多 32 人，6 关依次淘汰，决出 1 名冠军，约 9 分钟 |
| 可靠性目标 | 一场 Demo 能顺利跑完即可；不做断线重连、反作弊、多房间 |
| 主题句 | 市会散，人会回来 |

**一句话**：全场扫码，从汉代锦官城一路赶集到清末东门码头；每关一个月市，每关淘汰一部分人；最后一人在灯楼顶上“蟾宫折桂”，全场在大屏上一起走进今天的锦江十二月市。

## 2. 设计原则

1. **能跑完**：只有两套玩法引擎（网格、拾取）；玩家之间不发生任何碰撞和互动，只和地图互动。
2. **一眼认出是哪个市**：每关的核心动作和这个市卖的东西、做的事直接相关。
3. **有起伏的千年**：兴 → 盛 → 极盛 → 落 → 再生 → 归，低谷取自史实，表达克制。
4. **有限奇观**：交子雨、风起转场、结局，共 3 处。

## 3. 历史底座与叙事

- “成都十二月市”通常追溯到北宋赵抃《成都古今集记》：正月灯市、二月花市、三月蚕市、四月锦市、五月扇市、六月香市、七月七宝市、八月桂市、九月药市、十月酒市、十一月梅市、十二月桃符市。各市多在大慈寺一带，元代以后渐衰。
- 十二个市在宋代是**同一年里按月轮转**的。本作把每个市挂在它**最有故事的历史时刻**上，按时间先后排关卡，因此月份顺序与关卡顺序不同。
- **叙事只靠每关开场的一张史实卡**（纯文字，6 秒，史实依据与规则说明合在一起），不做向导角色和锦卷进度。
- 锦江区的现实锚点：大慈寺、锦江之名（濯锦传说）、东门码头的成都十二月市博物馆（2022 年开馆）。水井坊遗址是否属于锦江区**待核实**，核实之前不写进史实卡。

**情绪曲线**

```
强度 5 |        灯市  七宝市                 桂市  结局
     3 |  锦市                       酒市
     1 |                     市散
       +------------------------------------------------
          汉    盛唐  北宋   宋元之际   清初   清末民初  当代
```

## 4. 一局流程（约 9 分钟）

| 阶段 | 时长 | 手机 | 大屏 |
|---|---|---|---|
| 入场 | 不限 | 扫码 → 输入名字 → 选颜色 → 站在第 1 关的平台上等待，可以自由跑跳 | 二维码、在场人数、平台俯视 |
| 开局 | — | 房主按“开始” | — |
| 每关 | 6 秒卡片 + 3 秒倒数 + 60 秒游玩 + 5 秒结算 ≈ 75 秒 | 史实卡 → 3、2、1 → 玩 → 晋级/淘汰大字 | 同步显示全场俯视、卡片、晋级人数 |
| 关间 | 2 秒 | 淡入淡出，同时换平台皮肤 | 同步 |
| 风起（第 3→4 关） | 8 秒 | 文字卡 + 平台渐暗 | 播放视频 |
| 再生（第 4→5 关） | 6 秒 | 文字卡 | 播放视频 |
| 结局 | 45–60 秒 | 显示“冠军 xxx”和自己走到第几关 | 播放结局视频，叠加名单与合影 |

**视频只在大屏播放**，手机上只显示文字卡和结局页。

**房主控制（保证 Demo 能跑完）**：**大屏页面就是房主**，上面有“开始”“跳过本关”“直接结局”三个按钮。任何一关卡住时，可以手动跳到下一关。

## 5. 核心系统

### 5.1 房间与人数

- 只有一个房间，上限 32 人；满员后扫码的人只能看大屏。
- 锦市分队：8 人及以上分 4 队，4–7 人分 2 队，少于 4 人不分队。
- 某一关开始前只剩 1 人时，直接进入结局。
- 关卡状态和计时由**服务器**负责，手机只负责自己的位置和上报事件。

### 5.2 淘汰与晋级（以 32 人开局为例，比例可调）

通用公式：晋级人数 = clamp(四舍五入(在场人数 × 晋级比例), 2, 在场人数 − 1)。并列、全员掉落等边界情况见 [levels/00-common.md](levels/00-common.md)。

| 关 | 规则 | 人数 |
|---|---|---|
| 1 锦市 | 4 队涂色，面积最小的一队淘汰 | 32 → 24 |
| 2 灯市 | 文字题三选一，站错区域掉落；一直出题到剩约 70% | 24 → 17 |
| 3 七宝市 | 交子雨，捡得最少的约 35% 淘汰 | 17 → 11 |
| 4 市散 | 踩砖消失，剩约 60% 时结束 | 11 → 7 |
| 5 酒市 | 个人运粮，最先运满 3 袋的约 60% 晋级 | 7 → 4 |
| 6 桂市 | 塌阶冲顶，第一个登顶的人夺冠 | 4 → 1 |

### 5.3 观战

被淘汰后手机切换为和大屏一样的全场俯视画面，不做切换跟拍对象和表情。

### 5.4 外观

- 玩家只选身体颜色；锦市分队时，叠加队伍颜色的描边。
- 每关所有人统一戴上这个时代的同一顶帽子（汉介帻、唐幞头、宋东坡巾、宋元斗笠、清瓜皮帽；清末民初复用清代瓜皮帽换色），共 5 个模型；冠军结局时换成桂冠。

## 6. 操作与界面（手机）

- **横屏**。iPhone 无法锁定横屏，竖屏时显示“请横过来”。
- **左下**：浮动摇杆。**右下**：一个跳跃键（短按短跳、长按跳高）。不做飞扑，不做抓人。
- **顶部**：关卡名、倒计时、“晋级 x/y”。
- **镜头**：每关一条固定的斜俯视跟随机位，玩家不能转视角。
- **文字**：游玩过程中只出现短句，最小字号 16px，题目同时打在大屏上。
- 入场页的“进入”按钮顺带解锁音频（手机浏览器需要用户先点一下才能出声）。

## 7. 两套玩法引擎

### 7.1 网格引擎（锦市、灯市、市散、桂市）

- 平台由正方形地砖组成，每块地砖有三种状态：**颜色**（锦市涂色）、**消失**（市散、灯市塌陷）、**塌落时刻**（桂市台阶）。
- **和玩家无关的事件**（灯市塌陷、桂市逐级塌落和缺口）按“服务器下发的开始时间 + 随机种子”推算，所有手机结果一致，不需要逐块同步。
- **和玩家行为有关的事件**（锦市涂色、市散和桂市的踩踏消失）：手机上报踩到的地砖，服务器裁决后广播染色结果或消失时刻。

### 7.2 拾取引擎（七宝市、酒市）

- 场上的物品按服务器给的种子生成。玩家走到物品附近就拾取，并上报服务器；服务器按先到先得裁决，再广播该物品已被拾走。
- 酒市额外增加一个交付区：带着粮袋走进本人的交付区就计数一次。

### 7.3 角色

- 移动加跳跃，自写运动学，不接物理引擎。
- 角色与地砖和平台碰撞；**玩家之间不碰撞**，可以互相穿过。
- 掉出平台下方一定距离，就判定淘汰。

## 9. 美术方向

- **2026-10-27 视觉定稿**：[六关折纸市集概念设计](concepts/README.md)已通过 Claude Opus 逐图与系列验收；设计思路、时代背景、来源与验收标准见[系列简报](concepts/series-brief.md)。
- **3D Q 版折纸、纸雕与立体书风格**：薄纸边、折面、叠层和低对比纸纹构成统一语言，颜色与轮廓保持清楚。
- **角色**：统一比例的折纸小人，以米白剪纸描边和较鲜明衣色区分玩家与外围群众；按朝代调整衣帽，清代两关采用圆帽、短褂等线索，不沿用汉宋衣冠。
- **场地**：抬高的纸台/纸阶保留清楚玩法区域，周边用连续店铺、商品交易、制作、搬运和前中后景人流还原热闹市场。市散表现同地人群收摊离场，保留低谷；周边人气是视觉表现要求，不据此新增群众互动玩法。
- **资产来源**：全部由 AI 生成。先用图像工具定风格并出单件设定图，再用图生 3D（如 Meshy）以低模模式生成，角色自动绑骨并套用预设动作。流程见 [game-tasks.md](game-tasks.md)。
- **时代主色**：汉 赭红/玄黑；盛唐 金/朱；北宋 青绿/素白；宋元之际 灰褐/风沙色；清 青灰/暖木；清末民初 夜蓝/桂黄；当代 暖灯/霓虹点缀。

## 10. 音频

每个时代一段 AI 生成的循环配乐（如 Suno 付费版），市散关只有风声；音效同样用 AI 生成（如 ElevenLabs）。音效：跳、落地、晋级、淘汰、倒数、拾取、交付、地砖碎裂。

## 11. 技术方案

| 层 | 选择 | 说明 |
|---|---|---|
| 客户端 | three.js r180 | 与现有转场原型同版本 |
| 联机 | Node + WebSocket（可选 Colyseus 房间） | **各端自己模拟、服务器只转发**：每台手机模拟自己的角色，每秒上报 10–15 次位置；服务器负责转发位置、下发关卡开始时间和随机种子、汇总淘汰与拾取结果 |
| 判定 | 客户端自报 | 掉落、拾取、交付都由手机自己上报，服务器只做先到先得和计数；不做反作弊 |
| 关卡状态 | 服务器 | 服务器负责关卡流程、计时、晋级判定 |
| 其他角色 | 位置插值 | 别人的角色按收到的位置平滑插值显示 |
| 大屏 | 同一套客户端的“观众模式” | 不操控角色，固定俯视，开后期特效；兼任房主；播放过场与结局视频 |
| 部署 | 一台云服务器 + 静态资源 | 现场准备专用路由器，以 4G/5G 作为备用 |

**性能预算（手机）**：
- 渲染：每帧不超过 120 次绘制调用、不超过 15 万三角面。角色带骨骼动画，无法用实例化合并，每个角色不超过 2,000 三角面；远处的角色降低动画更新频率。
- 资源：首包不超过 15 MB（视频只在大屏播放，不计入）。
- 光照与后期：卡通无光照着色，不开实时阴影和后期。

## 12. 内容与史实规范

- 每张史实卡都标明【史实】、【传说】或【演绎】，并在内部附上出处；待核实的事实不写进卡片。
- 低谷只用风、熄灯、空街、冷色表达，不出现兵器、伤亡和破坏动作。
- 建议请主办方或在地文化机构审阅全部史实卡和题库。

## 13. 开发里程碑与砍功能顺序

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M0 | 扫码进房，多台手机同场移动和跳跃，大屏能看到所有人 | 10 台以上真机同时在线不卡 |
| M1 | 网格引擎 + 市散 + 房主按钮 | 能完整跑一关并淘汰 |
| M2 | 锦市、灯市、桂市（都基于网格引擎） | 四关连着跑完 |
| M3 | 拾取引擎 + 七宝市、酒市 | 六关连着跑完 |
| M4 | 史实卡、帽饰、过场与结局视频接入 | 一整局能完整演示 |
| M5 | 美术替换、音频、打磨 | — |

**进度落后时，按此顺序砍**：酒市 → 七宝市（拾取引擎整个不做）→ 风起、再生视频改成文字卡 → 结局改成名单定格。最小可演示版本是：锦市 → 灯市 → 市散 → 桂市 + 名单结局，只依赖网格引擎。

## 14. 风险

| 风险 | 应对 |
|---|---|
| 手机性能参差 | 低端机降低渲染分辨率；资源尽量小 |
| 现场网络 | 专用路由器，4G 备用；每台手机每秒只发十几个小包 |
| 某关卡住 | 房主“跳过本关”按钮 |
| iOS 浏览器限制（无法锁横屏、无法全屏） | 竖屏提示、入场引导 |
| 题目难度 | 题库提前找人试玩 |

## 15. 待定

1. 现场预计人数、大屏、网络条件。
2. 服务器部署方式（云服务器还是现场局域网）。
3. 史实卡和题库的审阅方。
4. 当代影像所用素材的授权（结局视频）。
