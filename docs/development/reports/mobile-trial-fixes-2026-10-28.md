# 手机试玩反馈修复记录

基于用户提供的横屏 Chrome 截图和本机 Chrome 的触控模拟；未在真实手机、微信、系统软键盘或现场网络复测。

- 全屏：入场点击尝试标准 Fullscreen API，游戏中也可手动切换；失败时仍能入场。浏览器是否真正隐藏自身界面由浏览器和宿主决定。模拟 Chrome 中检查了进入、退出、再次进入，以及不支持时的提示和入场。
- 横屏入场：按可视视口高度布局，紧凑显示表单并支持滚动。本机模拟了 920×280、667×230、844×390 的视口尺寸和变化，未模拟真实手机键盘。
- 视频：手机视频原使用 `object-fit: cover`，宽横屏会裁切画面；改为 `contain` 并在两侧留黑，开场素材元数据为 15 秒。服务端按统一时间切换，加载或播放延迟仍可能缩短实际播放时间。
- 移动：锦市服务器将角色限制在 x/z ±9.6，按 5 单位/秒移动，从出生点持续走几秒可抵达边界。本机触控模拟覆盖到达边界、反向移动、释放停止、双指移动加跳跃及失去指针捕获后停止；场地边缘增加标线和提示，本地预测不再跨出同样的边界，摇杆新增方向反馈。用户遇到的卡住是否还有其他原因，不能仅凭模拟确定。
- 构建与 `apps/test/mobile-viewport-touch.test.ts` 通过。此前相关浏览器、镜头、视频回退回归通过，但其中部分执行期间开发服务器发生了热更新；具体以最终独立重跑为准。

模拟截图：[入场](mobile-trial-2026-10-28/jinjiang-mobile-entry.png)、[开场视频](mobile-trial-2026-10-28/jinjiang-mobile-video.png)、[游戏画面](mobile-trial-2026-10-28/jinjiang-mobile-playing.png)。

[Cursor Grok 4.7 独立复核](grok-mobile-trial-review-2026-10-28.md)与修复并行进行：复核之后，已补上摇杆失去捕获的处理和测试、将全屏失败提示改为「无法切换」、避免提示计时器相互覆盖，并将两条提示分开。复核指出的真实软键盘、微信兼容和视频可视区域问题仍缺少真机证据；对其关于摇杆捕获及提示内容的描述应以本段后续修复为准。

[第二次只读复核](grok-mobile-trial-recheck-2026-10-28.md)确认上述变更在源码中存在，并指出游戏画面仍以布局视口为准、边界提示使用服务端坐标、缺少微信和软键盘实测等限制；该复核未运行测试。复核之后，入场请求全屏失败也会显示提示，且模拟用例覆盖此路径。本机再次运行了触控用例和构建，均通过。

另外，机器人功能的上一次独立复核发现：房间超过 32 人后，移除机器人不会让原观战玩家自动补位；重置后的机器人跳跃序号也可能残留。此轮未更改服务端，问题尚未修复，不应视为完整验收通过。

2026-10-28 后续修复：在房间等待阶段移除机器人时，有空位则按加入顺序补入已连接的观战玩家；观战玩家断线后重新连接时也会尝试补位。机器人每次进入新对局时重置输入与跳跃序号。真人客户端也按对局重置跳跃序号，断线恢复同一局时保留服务端输入游标。服务端定向测试覆盖满房候补、候补重连及机器人跨局跳跃；浏览器测试覆盖同一个真人页面跳跃后重开不自动跳跃。以上不能代表所有房间边界及整个 MVP 已通过。

后续弱网回归曾出现两类失败：[首次回归](acceptance-simulator-current-2026-10-28.log)松手后 1.5 秒的画面与已到达客户端的服务端坐标差 0.344 米，超过测试的 0.3 米；调整停止输入时的平滑收敛速度。复测随后连续两次在 10 次断线后无法继续移动，[诊断](browser-network-diagnostic-2-2026-10-28.log)显示玩家已连回且服务端收到输入，但过期恢复请求的失败回调将入场层显示在游戏上方。对重连尝试增加代次并忽略过期结果后，[定向测试](browser-network-race-fixed-2026-10-28.log)通过；随后新增等待旧请求超时后入场层仍隐藏的断言，正在完整回归中验证。此次调整仍是视觉平滑校正，不是逐输入精确回放。

2026-10-28 最终阶段补充：使用 Xcode iPhone 16 Pro / iOS 18.5 模拟器 Safari，在独立临时服务上分别查看[竖屏](simulator-entry-current-2026-10-28.png)与[横屏](simulator-entry-landscape-current-2026-10-28.png)入场布局，表单可见。截图不证明软键盘、多指或真机兼容。此次网络回归及机器人跨局修复后又引入了跨关跳跃游标保护，见 [Grok 复核](grok-level-cursor-review-2026-10-28.md)。空中按跳不会产生二段跳或落地后自动起跳；超过 300ms 才被采样的过期跳跃会丢弃，这两条行为已单独测试。断线未采样跳跃仅能由同一页面的内存游标补发，页面刷新后无法保证补发；逐输入精确回放尚未实现。

2026-10-28 用户反馈入场前点击全屏无响应：浏览器命中测试证实全屏按钮中心命中的是覆盖全页的 `#entry`。第一次只提升按钮层级仍因父级堆叠上下文而失败，失败记录为 [日志](fullscreen-entry-click-2026-10-28.log)；改为提升 HUD 父级并只让按钮接收指针事件后，[触控回归](fullscreen-entry-join-2026-10-28.log)通过，覆盖入场前全屏进入/退出/再进入、全屏状态下入场、入场后的全屏操作，以及移动和双指测试。真实手机浏览器仍需用户复验。

同日新增受管理令牌保护的 `/admin/diagnostics` 和只读观测脚本，记录玩家连接状态、坐标、当前输入方向、输入序号、接受/拒绝及 tick/广播时间。服务端诊断测试和构建通过。旧房间的状态流显示在七宝市玩家有连续移动，市散掉落后被淘汰；观察期间未捕获此前“走不动”的原因。新诊断后端单独运行，避免中断当前房间。[Grok 复核](grok-live-diagnostics-review-2026-10-28.md)指出诊断提示只能作线索；之后调整了微小输入、最近拒绝和服务端 tick 延迟的提示判定，仍不能把单秒净位移当作确定原因。
