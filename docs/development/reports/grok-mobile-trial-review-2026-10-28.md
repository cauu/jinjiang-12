# Cursor Grok 4.7 手机修复只读复核

复核与后续修复并行，以下是其当时看到的代码版本；相关后续改动和仍未验证事项见 mobile-trial-fixes-2026-10-28.md。

我按只读方式看这四处改动，重点核对全屏、短视口、视频裁切、摇杆和边界提示，以及测试覆盖是否够。这几处改动在桌面 Chromium 的短横屏里能串起入场、全屏、视频 `contain`、推到边缘再反向移动和松跳跃键，但全屏失败提示、键盘顶起视口、摇杆失焦和边界提示都有明确缺口。测试只守住了其中一条成功路径，不能当成真机或整包验收。

## 明确缺陷

**全屏失败被说成「不支持」，而且提示会被提前关掉。** `enterFullscreen` 把 `fullscreenEnabled === false`、没有 `requestFullscreen`、以及调用被拒绝，都走同一句「当前浏览器不支持全屏」。权限策略、手势已失效、或正在进入全屏时，这句话是错的。每次失败又各开一个 4 秒定时器，后一次失败的提示会被前一次的定时器提前藏掉。入场提交用的是 `enterFullscreen(false)`，失败时不提示；没有用户手势的会话恢复也不会进全屏。标准 API 之外没有 `webkit` 前缀，iOS Safari 上文档全屏通常直接失败，只能事后点按钮才看到说明。

**键盘只改了入场层，游戏画面和摇杆仍钉在布局视口上。** `--visible-top` / `--visible-height` 只用在 `.entry`。`#stage`、`#message` 视频和摇杆仍是 `position: fixed` 相对布局视口，`SceneView.resize` 也只听 `window.resize`。横屏软键盘或地址栏把可视区压矮时，入场表单会跟着缩，视频和摇杆不会；`html, body { overflow: hidden }` 还可能把铺满布局视口的视频裁掉一截。`object-fit: contain` 只保证视频元素内部不裁，挡不住元素本身超出可视区。

**摇杆丢掉指针捕获后会一直走。** `pointerup` / `pointercancel` 才会把输入清零，没有 `lostpointercapture`。系统手势把捕获抢走时，`x`/`z` 保持原值，100ms 的定时器会继续发送。跳跃键单独释放这条，测试覆盖了；摇杆自己丢捕获，没有。

**边缘提示和全屏提示叠在同一位置，而且只跟「服务端位置 + 当前输入方向」。** 两者都是顶部居中、`z-index: 5`，不支持全屏的提示会盖住「已到场地边缘」。提示条件是位置超过 ±9.3 且摇杆仍朝外；人已经贴在 ±9.6 的钳制边上、但摇杆回中或改成沿边滑时，提示会消失。本地预测先钳到 ±9.6 再向服务端插值，提示看的是服务端坐标，网络慢时会晚于人已经顶到墙上的时候。

键盘本身还有两个行为问题：方向键在焦点不在输入框时会 `preventDefault`，短视口里表单需要滚动时方向键滚不动；空格的 `keyup` 不看焦点，只要曾经按下就会把跳跃松开。

## 测试实际守住了什么

`mobile-viewport-touch.test.ts` 这一个用例，在 920×280、有触摸的 headless Chromium 里做了这些事：

- 入场表单和面板落在 280px 高度内
- 支持全屏时，入场手势能进入、退出、再进入
- 过场视频算出 `object-fit: contain`，并且能播过 0.25 秒、时长约 15 秒
- 摇杆向右能让服务端 `x > 9.3`，提示出现，本地 `data-player-x <= 9.61`，再向左能离开，松手后停住
- 跳跃键按下再松开时，摇杆移动不中断
- `fullscreenEnabled = false` 时，点全屏按钮会看到提示，且不会进入全屏

截图只写到 `/tmp`，没有参与断言。

## 测试没守住的部分

- 没有把可视视口改矮或模拟软键盘，也没有断言 `--visible-height`、摇杆和视频的包围盒仍在可视区内
- 没有量视频显示宽高比，`contain` 被写对但元素被视口裁切时，测试仍会过
- 不支持全屏只测了按钮；没测入场失败保持沉默、提示文案、4 秒后消失、以及连续点击互相取消
- `requestFullscreen()` 被拒绝、以及带前缀的旧实现，都没测
- 边界只推了 +X，没有 -X / Z，也没有贴边后松摇杆提示应消失
- 摇杆 `lostpointercapture` 只被记进事件数组，没有断言人物停住
- 键盘移动、空格跳、输入框里按键不应抢操作，都没有用例

所以：短横屏入场和「浏览器支持全屏」这条链路有自动化证据；不支持全屏的真实原因、键盘把可视区压矮、视频是否被视口裁切、摇杆失捕获后是否粘滞，目前都没有被测到。
