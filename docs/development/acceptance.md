# 白模 MVP 验收标准与执行清单

状态：首版执行基线，未标完成。目标是用占位美术、题库和四段占位视频，验证手机端、大屏端与服务端能完成多人六关游戏。验收基于证据；构建成功或单个自动化测试通过不等于整体验收通过。

## 1. 判定与报告

每项记录：测试日期、版本/工作树、环境与配置、场景、预期、实际数据、证据（日志、截图/录像或测试报告）、结果。结果只能是 **通过 / 失败 / 未执行 / 被外部条件阻塞**。只有 P0 所有项目通过，才能将浏览器白模 MVP 标记为通过；模拟环境验收还须通过第 6 节。失败先复现、定位、修复、重跑失败项及受影响的回归；不得通过改弱阈值或删除场景把失败改成通过。阈值变更须记录原因并由项目方确认。

初始量化阈值是研发基线，运行环境和方法固定后才可横向比较。无法测量时标未执行，不用“看起来正常”代替测量。素材本身和史实的最终验收不属于白模验收，但四段视频必须能用当前占位文件完成播放及兜底测试。

项目方指定 Cursor 的 Grok 4.7 作为独立验收人：每个待验收阶段，由实现者先完成实现和验证并提供版本、命令、环境与原始证据；验收人独立检查相关标准及证据，按项标记结果并给出问题。未通过由实现者修复、重测并提交复验，通过后再推进对应后续阶段。独立审查不能替代本清单要求的模拟器和浏览器实际测试；无法取得证据的项目继续标未执行或被外部条件阻塞，不能由模型推定通过。最终交付须同时满足本清单和手机端体验清单的全部适用门槛。

## 2. P0 浏览器与联机验收

| ID | 验收场景与阈值 | 证据 / 执行环境 |
|---|---|---|
| A01 | 同一局域网内大屏展示可扫码地址；两个独立浏览器会话扫码地址进房，名字和人数与大屏一致；重复 10 次 10 次成功。 | 浏览器自动化记录，核对二维码编码的地址；微信入口按第 6 节模拟。 |
| A02 | 拖动摇杆至少 0.5 秒，服务端位置和画面角色均朝对应方向移动；释放后 0.5 秒内停止持续移动；点击跳跃后角色上升并落地。四个方向各通过一次。 | 真实浏览器指针事件 + 服务端快照及渲染坐标；不能只断言按钮被点击。 |
| A03 | 在无拥塞测试环境中，按下操作到客户端首个对应方向的画面更新，95% 不超过 100ms；至少采样 100 次、记录全部样本。 | 浏览器指针事件到角色渲染坐标变化的单调时间；剔除首个载入及隐藏标签页，并记录网络条件。不能用按钮高亮或输入发送时间代替人物画面。 |
| A04 | 分别用 2、10、30 个独立浏览器会话，或资源不足时明确标未执行；30 人加入同一房间，仍在比赛中的玩家逐关实际操作、淘汰玩家继续观战；整局六关均实际进行，最终每个会话可核对同一冠军及各关结果。整局使用默认规则和时长；不得靠延长保护时间绕过玩法。必要时多个用例覆盖不同人数分支。 | 浏览器自动化会话与日志；30 个 Socket.IO 模拟连接不等同 30 个浏览器。 |
| A05 | 服务器状态为唯一结果；竞争同一交子只能一人得分，所有客户端一致；地砖、淘汰、成绩、冠军一致。网络恢复后 2 秒内，所有客户端当前阶段和结果与服务端一致（从客户端确认恢复连接时起计）。 | 并发/网络模拟测试与逐端快照比较。 |
| A06 | 玩家刷新、断线恢复各执行 10 次，均恢复相同身份及服务端当前阶段；若已淘汰进入观战，不复活。更换设备或清除本地数据不纳入恢复承诺。 | 浏览器独立上下文、网络切断及恢复；记录 20 次结果。 |
| A07 | 大屏开始、跳关、直接结局、重开分别执行 10 次，均达到对应阶段；重复同一请求不造成多次跳关。 | 真实大屏页面点击与 Socket.IO 请求重试测试。 |
| A08 | 开场 15 秒、风起 8 秒、再生 6 秒、结局 50 秒四段均能实际播放；文件缺失、播放失败或中途重连时仍按服务端时间推进，不能卡关。 | 浏览器检查播放时钟与服务端时间轴，含失败注入；允许视频画面不同步。 |
| A09 | 30 个模拟客户端加入后，在约 100–300ms RTT、抖动和 3 次断线场景中完成对局，全部恢复且最终冠军一致；记录 RTT 分布和拒绝操作原因。 | TCP 代理测试；不代表无线丢包及真实设备。 |
| A10 | `npm ci`、类型检查、两端生产构建、全部后端及浏览器验收测试退出码均为 0；测试代码和运行命令保存在仓库。 | 记录命令、完整输出、Node 版本与运行平台。 |

## 3. 六关玩法验收场景

| 关 | 至少覆盖的可观测场景 |
|---|---|
| 锦市 | 4 队、2 队、个人模式；踩格染色、覆盖后面积变化、面积最小方淘汰、平分规则。 |
| 灯市 | 三个区域可辨；每题显示题号和作答倒计时，截止时以服务端角色位置判定（含空中）；答错淘汰，存活者继续答题，最多五题结束，只剩一人时揭晓后提前结束；无人淘汰也可结束，全员淘汰则无人晋级、无人夺冠。 |
| 七宝市 | 交子下落后拾取、到期消失；竞争同一物品仅一人得分；排名和并列规则。 |
| 市散 | 保护期不塌；保护期后站立地砖触发；空中经过不触发；踩踏后延迟消失；掉落、到时与全员掉落均有结果。 |
| 酒市 | 单人最多一袋，四个角均能交付，每袋只计一次，达标立即晋级；掉落归还、补充和到时排名。 |
| 桂市 | 可通过实际移动和跳跃抵达终点；缺口、踩踏和逐排塌落可见且与服务器一致；抵达、全部掉落和超时均有唯一冠军。 |

场景必须包括**用户界面可见反馈**与服务器判定，后端单元测试只能作为补充，不能代替全部浏览器操作。正式约 15 题与史实校对由内容交付另行验收。

## 4. 前后端与可视验收

手机玩家的视觉、镜头与模拟触控量化标准另见[手机端视觉与游戏体验验收标准](mobile-experience-acceptance.md)，与本清单共同执行。当前这些新增标准均未完成验收。

- 手机端可以看到自己、其他玩家、规则、成绩和当前阶段；淘汰后可以继续观察；大屏能够看到玩家、全局、关卡结果及冠军。
- 玩家在局中根据操作立即产生本地画面反馈；服务端权威结果到达后进行修正。验证小偏差平滑、大偏差可快速恢复，不能由客户端显示决定成绩。**逐输入精确回放尚未实现，需要完成协议和验证后才能标通过。**
- 重要交互区域、答案、交付点、桂市终点清晰可辨；不能使用测试内部接口代替浏览器触控来宣称可玩。
- 四段占位 MP4 可播放、时间由服务端驱动；素材缺失或播放失败有可见占位。大屏冠军及手机观战/结局状态可见。
- 已有测试脚本只是一部分证据；未覆盖的页面、误差、操作延迟和完整浏览器对局仍须补测，不得将其视为通过。

## 5. 建议问题严重度

- 阻断：无法入房、不能操作、规则无法结算、不能完成整局、冠军不一致或无法从问题恢复。任何阻断问题未解决则验收失败。
- 严重：功能可继续但造成错误晋级、明显误导、反复异常回弹或过场导致长时间不同步。P0 场景不能有未解决严重问题。
- 一般：不影响玩法的布局或占位表现问题；记录后由项目方判断是否接受。

## 6. 模拟器与浏览器验收（最终交付前）

2026-10-28 项目方决定以模拟器和浏览器验收代替现场真机和真人试玩，原因是黑客松项目希望降低验收组织成本。此前现场设备数量、真人评分及真机帧率不再作为交付门槛；历史记录保留原测试条件，不将历史结果改写成新基线通过。

- 使用 iOS Safari 模拟器和具备触屏模拟的 Chrome，覆盖横竖屏及至少 16:9、19.5:9、20:9 横屏视口；记录模拟设备、系统/浏览器版本、视口和缩放。安卓可使用 Chrome 设备模拟，明确标注其并非安卓系统模拟器。
- 模拟微信 UA 检查外部浏览器引导、完整房间链接与复制兜底；在 Safari 模拟器检查入房和横竖屏布局，在支持全屏的浏览器验证由用户手势触发及失败兜底。不得据 UA 模拟宣称实际微信已验证。
- 默认规则与时长完成 2 次浏览器整局；其中至少一次包含 30 个独立浏览器会话，逐端核对关卡结果及冠军。按第 2、3 节完成其余人数、关卡、网络与视频场景。
- 按手机体验清单记录模拟环境的触控、画面与帧时间；模拟器性能、软键盘、真实多指和系统栏表现不能视作真机数据。真人主观舒适度及真实微信兼容性不在本次交付门槛内，后续有条件可补测。
- 服务器重启丢失内存对局是已知 Demo 限制；检查重启、重新扫码入口和房主兜底。正式视频、题库、艺术资源及其授权、历史文字审核仍按各交付包单独验收。
