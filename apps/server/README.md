# 六关联机后端 MVP

Node.js 22、TypeScript、Colyseus 0.18、Rapier；单服务进程、单房间、内存状态。同步与预测设计见 [实时同步与角色表现](../../docs/development/netcode.md)。服务端负责移动模拟、六关规则、淘汰结算、过场和冠军。手机端和大屏端已有白模入口，正式视频素材与完整前端验收仍待完成。

```sh
npm ci
npm run dev
npm run build
npm test
```

`npm run dev` 默认监听 `0.0.0.0:3000`，可设 `PORT`。进程启动时生成房间并打印房间 ID、管理端令牌；重启会丢失所有状态。`GET /health` 返回服务存活情况。只把房间 ID 放到玩家加入链接中，不把管理端令牌放进去。Demo 最多 32 名参赛者，满员或游戏期间新加入者观战。

## 协议

使用 Colyseus 0.18（客户端为 `@colyseus/sdk`）。房间 ID 由 `/admin/bootstrap` 提供，客户端以 `client.joinById(roomId, options)` 进入；状态通过 Schema 增量同步（`packages/shared/src/schema.ts`），字段名与 JSON `Snapshot` 一致。命令用 `room.request(type, payload)`，失败时以拒绝原因（如 `HOST_DENIED`）返回。

- 进入：管理端 `{host: token}`；新玩家 `{name, color?}`；恢复 `{resume: {playerId, resumeToken}}`。之后 `request('session')` 返回 `{playerId, resumeToken}`。同一玩家的新会话会以关闭码 4100 顶替旧会话。短暂断线由 SDK 在 20 秒内自动重连同一会话，超时后客户端用恢复凭证重新进入。
- `host:start`、`host:bots:add`、`host:bots:clear`：仅管理端。`host:skip`、`host:finish`、`host:reset` 需 `{requestId, matchId, phaseId}`，同一 requestId 重试不重复执行，旧局或旧阶段拒绝。
- 输入：`room.input()`，字段 `{x, z, jump, held}`，**每个固定步（30Hz）发送一条**，`jump` 只在按下的那一步为真。服务器按到达顺序逐条执行、逐条确认，同一 tick 到达多条时全部执行而不合并；300ms 无输入或断线则执行空输入步。倒数和游玩阶段之外的输入丢弃并计入诊断。
- `media:status` `{matchId, phaseId, status}`：仅作接收确认，不改变服务器阶段。
- 时间：`room.clock.serverNow()` 与服务器时间戳（`phaseEndsAt` 等）同一基准，即房间创建以来的毫秒数。

## 时间轴与媒体

默认流程：每关介绍 6 秒、倒数 3 秒、游玩最多 60 秒（灯市最多五题，每题 10+2+2 秒）、结算 5 秒；普通过场 2 秒，七宝市→市散风起 8 秒，市散→酒市再生 6 秒，结局 50 秒。阶段可按规则提前结束。前五关结束只剩一人时直接结局。可通过代码中的 `Options` 调整参数；开场视频 `introMs` 默认为 15 秒。

风起、再生、结局和开场阶段，快照的 `match.media` 给出素材 ID、服务器截止时间、时长、`displayUrl` 和 `phoneUrl`。放入仓库根目录 `assets/video/`（或使用 `MEDIA_DIR` 指定目录）的名称：

```text
intro.mp4         intro_phone.mp4
wind.mp4          wind_phone.mp4
rebirth.mp4       rebirth_phone.mp4
ending.mp4        ending_phone.mp4
```

服务端以 `/media/<名称>` 提供 MP4，支持单个字节范围请求；文件缺失返回 404，客户端应展示相同时长占位卡并按服务端时间继续。媒体回报不影响时间轴，重连无需精确跳到对应视频位置。手机是否播放独立视频仍需要在资源方案中确定；本协议允许手机用占位卡。当前已接入四段测试占位视频及手机副本，正式成片和真机播放验收仍待完成。

## 当前玩法实现与验证边界

- 锦市按人数分队、踩格染色与覆盖，面积最小队淘汰；灯市提供 5 道占位题，随机不重复出题，每题限时站区判定，答错淘汰；只剩一人时提前结束，否则最多五题后存活者晋级，全员淘汰时无人夺冠。正式约 15 题及史实审阅需内容方交付。
- 七宝市服务端生成和裁决交子；市散踩砖延迟消失、掉落及全员掉落兜底；酒市生成粮袋、携带、四角交付和晋级；桂市台阶、缺口、踏砖与定时塌落、抵达终点/掉落/超时均可产生冠军。服务端固定 30 tick，`Options.tickRate` 可调。
- 两人开局的单关演示允许只留 1 人，其他人数按关卡比例和最低 2 人规则。桂市的台阶和跳跃已用模拟输入走通一条样板路线；位置、缺口随机布局和操作手感仍需手机实测。
- `npm test` 包含 30 个本地真实 Colyseus 客户端、加速的六关与过场流程、恢复和一致冠军验证，以及规则边界与两人闭环。该测试为覆盖所有关卡而调长市散保护时间、缩短整局时长；它不等于 30 台真机、默认 9 分钟时长或弱网条件的负载验收。
- 手续上仅做临时匿名身份，不接微信授权。正式题库、视频、美术、二维码、移动端兼容、网络故障/服务器重启恢复、10 台以上真机与现场网络彩排仍需完成。无反作弊和持久化。

## 30 人延迟与断线模拟

```sh
npm run test:network
```

此测试启动真实 Colyseus 服务和 30 个客户端；每个客户端通过独立本地 TCP 代理，双向增加不同延迟、随机抖动及偶发延迟突增。测试通过三次强制断开连接并恢复身份，验证每名玩家至少有操作被服务端接收、六关与过场结束、30 人获得相同结果和冠军。客户端使用各自收到的状态发送操作，房主直连；输入每 5 次抽样一次服务端确认。测试的六关和过场时间被缩短，市散保护时间延长，以便覆盖所有关卡，不是默认完整时长或竞技表现验收。

2026-10-27 最终回归一轮：30 个客户端各采样一次 `time:ping`，往返时间最小 65ms、中位数 156ms、按客户端样本的 P95 为 301ms、最大 369ms；三次人为断开全部恢复；抽样输入 376 次接受、25 次以 `INPUT_NOT_ALLOWED` 拒绝。这个错误可能表示服务端已离开游玩阶段或玩家已淘汰；不能仅凭计数断言具体原因。结果受本机调度影响，随机种子固定不意味着每次字节分块与结果完全相同。

代理保持 TCP 字节顺序，可近似模拟延迟、抖动、偶发突增和整条连接中断；它没有模拟真实无线丢包与 TCP 重传、带宽上限、网络切换、手机性能、微信内置浏览器或画面播放。所有客户端和服务端运行在同一台电脑；该测试也无法验证本地预测及画面校正手感。仍需真实设备、真实网络和正式素材彩排。

## 前端白模和验收入口

仓库根目录 `npm run dev` 同时启动服务端、手机端（5173）和大屏端（5174）。大屏扫码地址使用当前大屏的主机名和手机端端口；手机真机连接需与开发机网络互通。`npm run test:browser` 运行两名浏览器用户的基本操作，`npm run test:latency` 测试 100 次本地指针到画面响应，`npm run test:30-browsers` 测试 30 个浏览器入房和开局；`npm run test:full-browser` 使用默认时长执行 30 个浏览器的完整流程，耗时数分钟。浏览器测试默认使用本机 Chrome，可用 `CHROME_PATH` 指定路径。

验收标准及尚未验证事项以 [白模 MVP 验收标准](../../docs/development/acceptance.md) 为准。当前本地预测是视觉层的近似修正，输入精确重放尚未实现；不要将已有自动测试结果等同最终验收通过。

### 试玩时观测

后端提供 `GET /admin/diagnostics`，请求头 `x-host-token` 须使用管理令牌。返回房间阶段、服务端 tick、最近一次广播、玩家连接/淘汰状态、位置与速度、服务端收到及采样的输入序号、当前输入方向、输入是否超时、收到/接受/拒绝次数及拒绝原因。不返回管理令牌或玩家恢复令牌；数据为进程内累计，重启后清空。

在项目根目录运行 `node --import tsx apps/server/src/observe.ts http://127.0.0.1:3500`，每秒输出一条 JSON；可在地址后加玩家昵称只观察该玩家。工具会自动取管理令牌并在服务重启时重新获取，不在日志中打印令牌。`hint` 是排查线索，例如 `phase_disables_control`、`player_eliminated`、`neutral_input`、`input_expired`、`server_tick_delayed`、`possible_boundary` 或 `nonzero_input_low_net_displacement`，不能代替对原始数据及客户端的分析。每秒采样可能漏掉短暂卡顿，角色没动也可能只是玩家没有操作。
